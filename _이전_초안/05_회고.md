# 말자람 노트 회고 (KPT)

> ⚠️ 이 회고는 **가상 진행을 전제로 쓴 예시**입니다. 실제로 진행한 뒤 본인의 경험으로 다시 쓰세요.

## Keep (잘한 것)
- **개발 3일 고정**: 기능을 늘리고 싶을 때마다 "3일 안에 되는가"로 잘라냈습니다. 덕분에 남은 기간을 사용자 테스트에 쓸 수 있었습니다.
- **지표를 처음부터 심은 것**: Day 3에 넣은 이벤트 로그와 `prompt_version` 컬럼이 없었다면 "개선했다"는 말만 남고 숫자는 남지 않았을 것입니다.
- **STT 사전 검증**: 2주차에 소음이 있는 환경의 샘플 녹음으로 정확도를 먼저 확인해서, 요약 수정 기능을 MVP 필수 기능으로 올릴 수 있었습니다.

## Problem (아쉬운 것)
- **iOS 녹음 이슈를 사용자가 먼저 발견**: 데스크톱 Chrome에서만 테스트했습니다. 모바일 웹앱인데 실기기 테스트가 늦었습니다.
- **알림을 MVP에서 뺀 판단**: 인터뷰에서 "숙제를 했는지 기억 못 한다"(P4)가 이미 나왔는데, 구현 난이도 때문에 미뤘습니다. 문제 정의와 기능 우선순위가 어긋났습니다.
- **표본의 한계**: 10명, 2주로는 계속 쓸지 알 수 없습니다.

## Try (다음에 할 것)
- 배포 전 체크리스트에 **iOS Safari·Android Chrome 실기기 녹음 10분 테스트**를 넣습니다.
- 기능 우선순위를 **인터뷰 문제(P1~P5)와 1:1로 매핑**해서 빠진 문제가 없는지 확인합니다.
- 가족 공유를 붙인 뒤 4주 리텐션(4주 차에도 회기를 등록하는 비율)을 측정합니다.
